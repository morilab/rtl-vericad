# アーキテクチャ

## 目的
本書は、単体ブラウザアプリと VS Code 拡張 WebView の両方を見据えた 2D CAD の基本アーキテクチャ方針を整理する。

## アーキテクチャ目標
- 早期フェーズでは単体ブラウザアプリとして素早く検証できること
- 最終的に VS Code 拡張 WebView 上へ無理なく移行できること
- CAD の振る舞いを React から独立させること
- 実行環境依存の差分を明確な境界に隔離すること
- MVP の先に機能拡張しても全面的な作り直しを避けられること

## 想定する上位構成

### 1. CAD コア
責務:
- ドキュメントモデル
- エンティティ定義
- 幾何計算
- 選択ロジック
- スナップロジック
- 編集コマンド
- Undo/Redo 履歴

制約:
- React に依存しない
- VS Code API に依存しない
- 描画実装に依存しない

### 2. アプリ UI
責務:
- React コンポーネント
- ツールバー
- プロパティ表示
- レイヤ表示
- キーボードショートカット接続
- ポインタイベントの受け口

制約:
- CAD ルールそのものを直接持ち込まない
- CAD コアへ問い合わせる形を基本とする
- ホスト API は定義済みの境界経由でのみ利用する

### 3. ホストアダプター
責務:
- 単体ブラウザ環境との接続
- VS Code WebView 環境との接続
- 永続化の橋渡し
- 通知や設定の橋渡し
- メッセージ送受信

制約:
- 実行環境固有の処理を上位へ漏らさない
- VS Code API の利用をホストアダプター内に閉じ込める

## 状態分離方針

### ドキュメント状態
永続的な図面内容を表す。

例:
- エンティティ
- レイヤ
- メタデータ

### ビュー状態
図面をどのように見ているかを表す。

例:
- ズーム倍率
- パン位置
- ビューポートサイズ
- 一時オーバーレイ

### ツール状態
現在の操作モードと途中状態を表す。

例:
- 現在ツール
- 作図途中のドラフト
- スナップ候補
- ドラッグ中の起点

## 描画方式の方向性
現時点では、描画方式は Canvas 系を第一候補とする。

理由:
- CAD 的なパン、ズーム、再描画に向いている
- SVG より大量図形時の負荷を抑えやすい
- 早期に GPU 前提の複雑な構成へ入らずに済む

ただし、これは現時点の仮説であり、最終決定ではない。

## ホスト境界の考え方
UI は、ブラウザ専用 API や VS Code 専用 API を直接呼ばず、共通のホストインターフェースに依存する。

ホストの責務候補:
- ドキュメント保存要求
- ドキュメント読込要求
- ユーザー通知
- 設定取得と保存
- クリップボード連携
- メッセージ受信

## 履歴モデル方針
Undo/Redo を後付けにしないため、すべての編集操作は履歴管理可能な単位で扱う。

候補:
- コマンド指向
- 操作差分指向
- 限定的スナップショット指向

現時点では、コマンドまたは操作差分ベースを有力候補とする。

## 主な設計リスク
- React コンポーネントの内部に CAD ロジックを埋め込むこと
- 永続化形式を内部モデルと同一視しすぎること
- UI コードの各所から VS Code API を直接呼ぶこと
- WebView 制約と相性の悪い依存関係を無計画に導入すること
