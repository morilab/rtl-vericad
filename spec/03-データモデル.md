# データモデル

## 文書の目的
本書は、2D CAD の内部データモデルの初期たたき台を示す。  
現時点では概念整理を目的とし、実装詳細を固定するものではない。

## 基本方針
- 内部データ構造は、編集しやすさと履歴管理のしやすさを優先する。
- 永続化形式は内部モデルに従属させる。
- 描画表現は内部モデルから導出する。
- 一時的な操作状態は永続データと分離する。

## 候補となる主要モデル

### Document
1 つの図面全体を表現する。

想定項目:
- 文書識別子（モジュール名）
- メタデータ
- レイヤ一覧
- エンティティ一覧

### Metadata
文書全体の補助情報を保持する。

想定項目:
- 文書名
- 作成者
- 作成日時
- 更新日時

### Layer
図形の分類と表示制御を担う。

想定項目:
- レイヤ識別子
- レイヤ名
- 表示状態
- ロック状態
- 既定スタイル

### Entity
個々の図形を表す。

共通項目候補:
- 識別子
- 種別
- 所属レイヤ識別子
- スタイル
- 幾何情報
- 任意メタデータ

候補となる種別:
- line
- rectangle
- text

## 座標と単位の考え方
- ワールド座標と画面座標を明確に分離する。
- スナップや幾何演算はワールド座標基準で扱う。
- ビュー変換によりワールド座標から画面座標へ変換する。
- 座標は単位を持たない（単位なし）ものとして扱う。

## ビュー状態の候補
- ズーム倍率
- パン位置
- ビューポートサイズ
- グリッド表示状態
- ホバー対象
- 選択矩形

## ツール状態の候補
- 現在ツール
- 進行中コマンド
- 下書き中図形
- スナップ候補
- ドラッグ起点

## 履歴モデルの候補
- コマンドスタック
- 不変スナップショット
- 差分パッチ

現時点での推奨:
- コマンド指向、または操作指向の履歴モデルを優先検討する。
- 無秩序な直接更新経路を避ける。

## 保留事項
- レイヤは内部モデルとして持つ前提をどこまで固定するか（ユーザー向けレイヤ機能は MVP 対象外）。
- style は entity 直指定を基本にするか、layer 継承を持つか。
