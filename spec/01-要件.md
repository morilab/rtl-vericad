# 要件

## この文書の目的
この文書は、2D CAD アプリケーションの初期要件を整理するためのものである。  
現在は使用検討および仕様策定フェーズであり、実装を開始する前に MVP の範囲と制約を明確化することを目的とする。

## 製品ゴール
- 最終的には VS Code 拡張の WebView 上で動作する 2D CAD を提供する。
- 初期段階では、同一アーキテクチャを前提とした単体ブラウザアプリで設計と操作性を検証する。

## 初期フェーズで重視すること
- 2D CAD として成立する最小限の操作体験を定義すること
- VS Code WebView への移行を妨げない設計制約を明確にすること
- CAD コアと UI の責務分離を前提に要件を整理すること

## MVP 候補機能

### 図形
MVP では、以下の図形を候補とする。
- 配線（線分）
- モジュール（矩形）
- テキスト
- 交点（結線）
- SVG アイコン（端子マークその他）

#### モジュール定義（MVP）
- 形状は矩形とする。
- 高さは可変とする。
- 幅は固定とする。
- 左辺または右辺の線上に端子を持つ。
- モジュール名とインスタンス名を持つ。
- モジュール名は矩形中央に縦横中央揃えで表示する。
- インスタンス名は上辺に沿って左揃えで表示し、テキスト左端が左辺上に一致、テキスト下端が上辺に一致する。
- モジュールは矩形の頂点 x4 がすべてオングリッドとなる。
- モジュール名およびインスタンス名は改行禁止とする。

#### 端子定義（MVP）
- 端子は名前（文字列）を持つ。
- 端子は同一グリッド上の重複を許さない。
- 端子名のテキスト表示はオングリッドとする。
- 端子名のテキスト表示は高さ方向（縦方向）を中央揃えとする。
- 右辺上の端子名は横方向を右揃えとし、テキスト右端が右辺上に一致する。
- 左辺上の端子名は横方向を左揃えとし、テキスト左端が左辺上に一致する。
- 端子名は改行禁止とする。
- 右辺上の端子は右側へのみ配線が可能とする。
- 左辺上の端子は左側へのみ配線が可能とする。
- 端子は以下のいずれかがオングリッドとなる。
  - 端子アイコン（SVG）の中心
  - 端子名テキストボックスの左右辺の中点 x2 のいずれか

#### 配線定義（MVP）
- 配線は縦横のみとする（直交配線のみ）。
- 斜め配線は扱わない。
- 結線は T 字結線のみとし、十字結線（クロス結線）は禁止する。
- インターフェース名とワイヤ名を持つ。
- 交差表示（ブリッジ等）は導入しない（軽量化のため）。
- 水平線と垂直線が交わるとき、結線するか否かは配線の信号名（ワイヤ名）が同一かどうかで決定する。
  - 同一であれば結線する。
  - 異なっていれば結線しない。
- 結線している場合のみ結線マーク（●）を表示する。
- 十字結線はそもそも禁止のため、自動配線では発生せず、ユーザー操作でも作れない。
  - 結線マーク（●）のあるグリッドは、配線の開始点・終了点として認めない（クリックしても操作が進まない）。
- 配線は以下の点がオングリッドとなる。
  - 開始点
  - 終了点
  - 交差点
  - 結線点
  - まがり点

#### テキスト定義（MVP）
- テキストの揃え（左/中央/右、上/中央/下）は、テキストボックスを基準に考える。
- テキストボックスは矩形とし、以下の 9 点（アンカーポイント）を持つ。
  - 頂点 x4
  - 辺の中点 x4
  - 中心 x1
- この 9 点のいずれかがオングリッドとなる。
- コメントテキストはテキストボックス内での改行を許す。それ以外のテキストはすべて改行禁止とする。
- テキストはテキストボックスからはみ出さないようにフォントサイズを自動で調節する。

補足（MVP の前提）：
- すべての図形はオングリッドとし、オフグリッドを許さない。
- グリッドの原点は常に左下とし、右方向、上方向にプラスとする。
- 交点（結線）は、線分の関係性（交差・端点接触など）から明確に導出できるものとして扱う（ユーザーが直接配置する図形とはしない）。
- SVG アイコンは表示要素とし、配置は行うが、要素となる線分の座標は使用しない（線分と幾何的に拘束しない）。

### 編集操作
MVP では、以下の操作を候補とする。
- 作成
- 選択
- 移動
- 削除
- 複数選択
- 操作キャンセル
- フィット（全体/選択範囲が画面に収まるよう表示を調整）
- 配置最適化（ブロック等の自動整列・自動配置）
- 配線最適化（配線の自動整形・最短化など）

#### モジュール自動配置（MVP）
- モジュールは上下移動（Y 位置）と高さ変更を行うが、X 位置は変更しない。
- モジュール幅の変更は行わない。
- 自動配置における高さ変更は、モジュールの上辺・下辺が端子と重ならない限り、なるべく高さを小さくする動作とする。
- モジュール自動配置において、配線と端子は移動しない。

#### フィット時の座標調整（MVP）
- フィットのタイミングでは、X または Y の値のいずれかがマイナスのグリッドに乗っているものがないように座標を調整する。

#### 自動配線（MVP）
- 配線は水平・垂直のみのマンハッタンルーティングとする。
- 探索アルゴリズムは A* を採用し、コスト関数は少なくとも以下を考慮する。
  - 通常曲がり：大
  - モジュール辺上曲がり：禁止
  - 他配線との近接：小
  - 交差：中
  - 距離：小
  - モジュール上通過：禁止
- 配線コストが下がるのであれば、端子は辺上を上下移動してよい。
- 配線コストが下がるのであれば、モジュールは高さを増減してよい。

### 表示操作
MVP では、以下の表示系機能を候補とする。
- パン
- ズーム
- グリッド表示
- グリッドスナップ
- 端点や中心点へのスナップ
- バードビュー（全体俯瞰のミニマップ表示）

### 描画レイヤ
描画順（下から上）は、以下とする。
- 背景、グリッド、メジャーなど
- ブロック・配線
- 交点、アイコン、テキスト
- 操作表示

### カラー定義（テーマ）
- カラー定義はセットで変更可能とする。
- デフォルト設定は以下とする。
  - 背景：白
  - グリッド：明るいグレー
  - モジュール
    - 線：青
    - モジュール名：暗い青
    - インスタンス名：紫
  - 端子
    - 端子名：暗い青
  - 配線
    - 線：暗い緑
    - 交点：暗い緑

### 履歴
MVP では、以下の履歴機能を必要条件とする。
- Undo
- Redo

### 保存
MVP では、以下の保存機能を候補とする。
- 内部 JSON 形式での保存
- 内部 JSON 形式での読込
- 外部 JSON 形式での保存
- 外部 JSON 形式での読込
- 保存のタイミングでは、X または Y の値のいずれかがマイナスのグリッドに乗っているものがないように座標を調整する。

## 非機能要件

### ホスト互換性
- UI 層はブラウザ互換環境を前提とする。
- VS Code WebView で動作困難な依存や実装方式を避ける。
- ホスト依存機能は host adapter を介して利用する。

### 応答性
- パン、ズーム、選択、基本編集が体感上ストレスなく行えることを目指す。
- 少なくとも MVP 規模の図面では、操作のたびに大きな遅延が発生しないことを目標とする。

### 保守性
- document state、view state、tool state を混在させない。
- CAD ロジックは React コンポーネントから切り離してテスト可能な構造を目指す。

## 初期段階では対象外とする候補
- DXF の完全対応
- 印刷やプロットの最適化
- 寸法拘束
- 高度な CAD 互換機能
- プラグイン機構
- リアルタイム共同編集

## 保留事項
- 対象用途をどこまで汎用 CAD に寄せるか
- レイヤ機能を MVP に含めるか（ユーザー向け機能としては MVP 対象外）
- 操作感を CAD 寄り、Figma 寄り、EDA 寄りのどこに置くか（CAD 寄り）
- 寸法や注記を MVP に含めるか
